# Finance plain-language audit (Cash, Suppliers, Finance overview)

Date: 2026-10-18. Read-only audit of markup and code; no screens were run. Line numbers are as of branch `codex/clerk-only-auth-20261017`.
Status key: FIXED = server-side wording already changed in this pass; OPEN = UI file or shared code, list only.

## High

1. **Zero is accepted as a "positive" provider settlement amount (server bug, found while testing).** `src/modules/settlements/persistence.ts:51` used `Decimal.isPositive()`, which is true for 0. A gross of `0.0000` passed validation and hit a database check, so the user got a blank 500. FIXED: uses `gt(0)`; invalid amounts now answer 400 "Gross amount must be positive" / "Enter an amount in dollars with at most 4 decimal places". Same `isPositive()` pattern remains OPEN in `src/modules/costing/persistence.ts:67,269,494,1219`, `src/modules/inventory/domain.ts:48,80`, `src/modules/creditors/domain.ts:149,371` (creditors/inventory guard zero elsewhere in places; verify each). Fix: replace with `.gt(0)`.
2. **Supplier screens show raw server text and drop validation detail.** `supplier-workspace.tsx:67-70,318,325` and `supplier-detail-workspace.tsx:77,266,271` show `message` verbatim. Zod failures return `{error, issues}` with no `message` (`src/platform/observability/index.ts:213`), so the user only sees the generic fallback and never which field is wrong. Fix: map `issues[].path` to field labels like cash does (`cash-workspace.tsx:161-175,515-560`); extract that helper into a shared file.
3. **Supplier errors with state codes reach the screen.** `src/modules/creditors/domain.ts:267,282` "Supplier document cannot transition from SUBMITTED to POSTED" (tests require substring "cannot transition", so left). Replacement: "This document has already moved on and cannot be changed this way." Also `domain.ts:157` INVARIANT messages and `application.ts:224` "`supplierId` is required" (field names are code identifiers), `application.ts:228` "SubmitSupplierPayment requires an expected version" (command names), `application.ts:169` "Idempotency-Key is required", `application.ts:132` "The idempotency key was reused with new data". Replacement for all four: "Something went wrong sending this. Reload the page and try again."
4. **Cash error banner for list loading shows the raw server message with no tailored help.** `cash-workspace.tsx:1187-1191` shows `error.message`; `:411-413,588-591` shows `contextError` raw under the title "Cash context unavailable". Fix: reuse `failureHelp()` wording, retitle "Cash could not be loaded", message "We could not load the cash position. Nothing was changed."

## Medium

5. **No retry on supplier command errors.** `supplier-detail-workspace.tsx:345` (context error, no button), `:505,597` (`actionError` with no "Try again"), `supplier-workspace.tsx:518` (create error, no button). Fix: add a "Try again" button that re-submits the form, as cash does (`cash-workspace.tsx:559`).
6. **Finance overview error states have no retry.** `src/app/finance/page.tsx:117-121` (partial failure says "Reload to try again" but has no button), `:213` and `:257-261` ("Reload the page to try again" text only). It is a server component, so use a small client `<ReloadButton>` or `<Link href={sameUrl}>Try again</Link>`.
7. **Technical wording in hard-coded UI strings.** `supplier-detail-workspace.tsx:282` and `:310` "an exact decimal amount" -> "an amount, for example 125.50". `:373` title "Submitted" + "submitted for posting review" (`:285-ish success messages`) -> "Sent for approval". `:448` "No posted movements" -> "Nothing recorded yet". `supplier-workspace.tsx:217,225` "Authorised supplier context could not be loaded" -> "We could not load your company details." `supplier-workspace.tsx:293` "Supplier code and legal name are required." -> "Enter the supplier's code and name." `finance/page.tsx:220` "context selector" -> "station picker at the top".
8. **Finance area names and status words.** `src/modules/approvals/action-center-model.ts:131,156,191,204` the "could not be checked" list says "Reconciliations", "Cost revaluations", "Provider settlements", "Customer credit" (jargon: "Reconciliations" -> "Shift reports", "Cost revaluations" -> "Stock cost changes", "Provider settlements" -> "Card and mobile payouts"). Same for area tiles "Settlements" and "Payables" in `finance/page.tsx:117` and `action-center-model.ts:34` -> "Payouts" and "Supplier bills".
9. **Fallback state labels.** `cash-workspace.tsx:254-259,1168,1240,1328,1409` `displayState()` turns any unknown code into "Some code" words (e.g. "In transit"). Known codes are labelled, but any new state silently leaks. Fix: fallback to "Updating" or throw in dev tests; add a test that every enum has a label. `supplier-format.ts:movementLabel` does the same for ledger movement types ("Invoice posted", "Payment reversed") - add a label map.
10. **Settlement-style server wording still technical (OPEN, e2e mocks assert some).** `src/modules/settlements/persistence.ts` "The provider settlement is stale", "Settlement currency must match provider account currency", "The provider account is not configured for this station". Replacements: "Someone else changed this payout. Refresh and try again." / "The payout must be in the same currency as the account." / "This account is not set up for this station." Left as is because `tests/e2e/provider-settlements.spec.ts:337-352` pins the stale text.
11. **Supplier create has no duplicate-code message check.** `persistence.ts` in creditors: a duplicate supplier code is a unique-key violation; verify it returns a plain 409 ("A supplier with this code already exists") rather than a 500 (generic "Supplier could not be created").

## Low

12. **Phone width (390px).** Cash and Finance tables stack into cards under 48rem via the shared `.data-table` rules (`src/design-system/styles/components.css:~1122-1183`, uses `data-label`). Risk is limited to cells without `data-label` (they fall into the `td:not([data-label])` rule) and the 6-column Deposits table (`cash-workspace.tsx:1362`): confirm each `<td>` there has a `data-label`. Suppliers use `list-row` cards. Finance cards and tiles have explicit mobile CSS (`globals.css:4048-4090`). `.cash-details dd` wraps long text. Low risk; verify visually at 390px.
13. **Numbers compared with `Number()`.** `cash-workspace.tsx:602,1219` `Number(collection.availableAtStation) > 0`. Only a sign check on a 4-dp string (safe below 2^53) but breaks the exact-decimal rule on principle. Fix: `exact(x).value.gt(0)` (`reporting/domain`).
14. **Money display rounds to cents.** `reporting/format.ts` `formatTileMoney` rounds half-up to 2 dp (documented, display only, uses Decimal). Cash deposit "Bank difference" and supplier overdue use it; a 0.004 difference shows "USD 0.00" and could hide a real mismatch. Fix: show "less than 0.01" when the value is non-zero but rounds to zero.
15. **Stale state after write.** Cash and supplier flows call `refresh()`/`loadDetails()` after success (good). The Finance overview is `force-dynamic` but is not refreshed after the user returns from a fix in another screen via client navigation cache; if Next's router cache serves the page, tile counts can lag. Fix: `router.refresh()` on focus or `export const revalidate = 0` plus `prefetch={false}` on the `finance-tile` links.
16. **Finance supplier check throws FORBIDDEN when no legal entity is selected** (`src/modules/approvals/action-center.ts:~88`), so Payables silently shows "Nothing waiting" instead of "choose a company". Fix: mark `unavailable` with a hint.
