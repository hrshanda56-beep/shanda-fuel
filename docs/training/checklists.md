# Daily shift and reconciliation checklists

Use the release-specific labels in the [guides](README.md). Keep completed copies under the station's approved records process; never include passwords or MFA codes.

## Daily shift checklist

- [ ] Own account signed in; correct organisation/entity/station/date/shift confirmed.
- [ ] Day open and intended shift OPEN; no duplicate day/shift created.
- [ ] Actual attendants verified; nozzle responsibilities confirmed separately.
- [ ] Pumps/nozzles, meter installations, fuel and active prices match setup.
- [ ] Opening readings checked against actual meters and saved evidence.
- [ ] Receipts and channel evidence retained; exceptions reported promptly.
- [ ] Closing readings verified; required boundaries/segments complete.
- [ ] Meter-close success confirmed from persisted state.
- [ ] Payments, expenses and physical cash count recorded accurately.
- [ ] Draft saved and reloaded; required variance explanations complete.
- [ ] Reconciliation submitted and SUBMITTED verified; reviewer notified under station procedure.
- [ ] Shift/day completion checked separately; unresolved items handed over.
- [ ] Account signed out; device secured.

## Reconciliation checklist

Record ID: ______ State/version: ______ Submitter: ______ Approver: ______

- [ ] Scope and reporting period correct; station timezone known.
- [ ] Attendants and evidence belong to this shift.
- [ ] Meter totals trace to sealed boundaries/segments and correct prices.
- [ ] Cash/POS/EcoCash/other channels entered once; references checked.
- [ ] Customer/account and approved-fuel attribution complete where required; gaps escalated.
- [ ] Expenses supported, correctly categorized and assigned to actual payment method.
- [ ] Cash physically counted; cash variance investigated separately from sales variance.
- [ ] Delivery/dip evidence checked; missing information marked incomplete.
- [ ] Required SALES/CASH/STOCK explanations recorded; differences remain truthful.
- [ ] Saved server totals reviewed after reload; no unsaved edits assumed persisted.
- [ ] Different authorized reviewer identified; permission and current MFA available.
- [ ] Return reason supplied if returning; correction/resubmission verified if applicable.
- [ ] Approval confirmed from persisted state; no ordinary edits after approval.
- [ ] Banking/provider follow-up recorded separately; approval not treated as settlement.
- [ ] Unresolved items assigned to a named contact with follow-up time.
