# First 30 minutes after an authorized release

This is a manual observation checklist, not a configured scheduled monitor.
Release authorization, production access and named primary/backup operators must
exist before use. No release or production request was performed for this task.
Use only <https://fuel.shandahr.com> for owner-facing verification.

| Window            | Authorized operator checks                                                                                                                                                                                                   | Evidence / stop decision                                                                                                                                                                                                                    |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Before minute 0   | Full approved SHA, immutable deployment ID/READY, canonical alias binding, CI/review, approved migration/hash evidence, current backup reference, compatible healthy target and incident contacts                            | Missing identity, migration compatibility or required approval stops release. Record exceptions and watcher before handoff.                                                                                                                 |
| 0–5 minutes       | GET health/readiness; watch correct-deployment runtime logs; legitimate operator sign-in/MFA/context/protected read                                                                                                          | Record UTC time, status, request ID and deployment. Total outage or isolation/corruption concern: P0 immediately. Readiness failure: P1/stop normal affected commands, involve DB/release owner. No five-minute grace for security failure. |
| 5–10 minutes      | Read-only dashboard/Daily Operations/reports and approved station switching; compare truthful empty/unconfigured states and station timezone                                                                                 | Record affected scope privately, safe errors/timings. No synthetic balances or test posting. Critical workflow blockage: P1.                                                                                                                |
| 10–20 minutes     | Watch 5xx, dependency/auth/step-up denials, conflicts, idempotency and audit append failures; approved Neon compute/connections/locks if accessible; ask actual station operator about close/reconciliation/payment problems | Check actual business state for ambiguous outcomes; preserve frozen retry attempts. Do not provoke errors, bad passwords, rate-limit bursts or financial writes to test monitors. Missing logs/metrics: NOT VERIFIED.                       |
| 20–30 minutes     | Repeat health/readiness and key read; verify logout/re-login within approved smoke, compare error/latency trend and current alias/SHA; review unresolved cases and audit/duplicate concerns                                  | Record observation duration and available sample count. Quiet traffic is insufficient proof of command/financial correctness. App rollback only after compatibility review and explicit approval.                                           |
| Minute 30 handoff | Record PASS/FAIL/NOT VERIFIED per check, incident references, open risks, evidence location, operator/backup, next check and owner acceptance                                                                                | Do not declare owner-ready with unresolved P0/P1 or missing required release gates. Continue an explicitly assigned manual watch if alerts remain unverified.                                                                               |

Use [incident playbook](production-incident-playbook.md) for symptoms and
[deployment/rollback](deployment-rollback-checklist.md) for recovery. Do not
restart, roll back, run migrations, change flags/ACLs or restore data from this
checklist. Record any authorized real business flow observed separately; a
read-only watch does not prove meter close, approval or financial posting works.
